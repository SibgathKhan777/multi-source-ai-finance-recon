Multi-Source Finance Reconciliation

A 5-minute walkthrough script. Every command below is real and copy-pasteable — run it live in your own terminal and browser while recording with Loom. Nothing here is staged; the numbers are whatever your machine actually returns.

Target length: 5:00 Format: terminal + browser, screen-recorded Voice: yours, live

Before you hit record

  1. Reset to a clean slate so the numbers below match exactly:
    cd backend && rm -f recon.db
  2. Start the backend in one terminal pane (leave it running):
    source ../.venv/bin/activate && uvicorn main:app --reload --port 8000
  3. Start the frontend in a second pane:
    cd frontend && npm run dev
  4. Open http://localhost:3000 in a browser tab and confirm the dashboard loads before recording.
  5. Arrange your screen so a terminal and the browser tab are both reachable without fumbling — split screen or quick Cmd+Tab.

1 · The problem

Say
"Reconciling money across a ledger, a payment processor, and a bank statement is normally a manual slog — checking that amounts line up, chasing down timestamp mismatches, guessing whether 'Razorpay Technologies' in one file is the same company as 'Razorpay' in another. I built a system that does that automatically, and — this is the part that matters — knows the difference between a case it can resolve with confidence and one that genuinely needs a human."
Do
Face camera or show your project folder in Finder/VS Code. No terminal yet — this is the hook.
0:25 – 1:00

2 · The pipeline, in one breath

Say
"It's seven phases. Ingest all three CSVs and flag — never drop — bad rows. Normalize everything onto one schema and convert every timestamp to UTC. Run a five-pass matching engine: exact match, tolerance match, batch net-settlement, and so on. Anything left over goes to an AI agent built with LangGraph, which reasons about near-misses instead of a human eyeballing three spreadsheets. What the agent won't touch becomes a routed exception. And a look-back window catches records that arrive late and revises the right match instead of creating a duplicate."
Do
Optionally show backend/ folder structure — one directory per phase — for two seconds while you talk.

1:35 – 2:40

4 · Hit the live API

Say
"This is the same backend running behind the dashboard — I'm just curling it directly so you can see there's no smoke and mirrors."
Do — type this 
$ curl -s http://localhost:8000/api/report | python3 -m json.tool
Point at match_rate (~0.79), total_canonical_records (67), and match_group_status_counts — matched / partial / unmatched / disputed.
Say
"67 records in, about 79% matched automatically. Let's see exactly what didn't."
Do — type this 
$ curl -s "http://localhost:8000/api/exceptions?status=new" | python3 -m json.tool
Five exceptions come back, each with a detail reason and a suggested_owner — engineering or finance_ops.
Say
"Let's zoom into one. This transaction's ledger and PSP records both say 5000 rupees, the PSP fee is 350 — but the bank credit only shows 4650. That's short by exactly the fee amount."
Do — type this 
$ curl -s http://localhost:8000/api/exceptions/EXC-00002 | python3 -m json.tool
Read the detail field aloud: "...matches the PSP fee (350.0) exactly: looks like a fee formula bug" — then note suggested_owner: "engineering", not finance.
2:40 – 3:10

5 · Where the agent draws the line

Say
"Before anything becomes an exception, a LangGraph agent gets first look at the near-misses. A blank currency field it infers as INR, since that's the only currency anywhere in the dataset. A 45-minute settlement delay it accepts as normal processing lag. A counterparty typo it recognizes against the crosswalk table. But — and this is the part I'm proudest of — it explicitly refuses to resolve a negative amount that should've been a positive sale. That's a genuine data-entry error, and the agent doesn't force a plausible-sounding match just because it technically could. It stays flagged, for a human."
Do
Stay on terminal, or briefly open backend/agent/reasoning.py and scroll past the resolver functions — no need to explain the code, just let it be visible.
